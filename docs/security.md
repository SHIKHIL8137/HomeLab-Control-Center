## Added in the release-candidate hardening

| Control                                                                                                                                                                                                                                                            | Where                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------ |
| Proxy requires `Authorization: Bearer <credential>` on every request, checked in constant time (both sides hashed first), **before** routing, so an unauthenticated caller cannot probe the allowlist; missing, wrong, malformed and oversized headers are refused | `apps/docker-proxy/src/server.ts`          |
| Proxy and API both refuse a short, badly-formed or trivially repetitive credential and refuse to start without one (fail closed)                                                                                                                                   | `server.ts`, `apps/api/src/config.ts`      |
| Credentials are read from mounted files (`*_FILE`) so they stay out of `docker inspect`, rendered config and logs (verified); error messages name variables, never values                                                                                          | `config.ts`, `compose.yaml`                |
| Network membership is not authentication: a container placed on the internal network without the credential gets 401 (verified)                                                                                                                                    | `deploy/compose.yaml`                      |
| Proxy accepts only canonical request targets: no `//`, dot segments, `%`-encoding outside the events filter, backslashes, control characters, absolute-form URLs or API-version prefixes; only `GET`                                                               | `apps/docker-proxy/src/policy.ts`          |
| Proxy limits: header, request and keep-alive timeouts, 16 concurrent requests, no request bodies, upstream cancelled when the client leaves, response size cap, bounded event window                                                                               | `server.ts`, `policy.ts`                   |
| Disk probes are accepted only if the path is a real mount point (from the kernel mount table), not tmpfs/overlay, and a "separate" disk is a different device from a valid reference disk                                                                          | `apps/api/src/providers/host.ts`           |

| `audit_events` is append-only in the database itself (triggers reject UPDATE and DELETE)                                                                                                                                                                           | `migrations/003_audit_append_only.sql`     |
| scrypt at N=2^15, r=8, p=3 with parameters stored per hash; stored parameters are bounded so a tampered row cannot exhaust memory; hashing is serialised; old hashes are upgraded at next sign-in                                                                  | `security/password.ts`                     |
| Sessions are rotated at every sign-in; the previous token stops working                                                                                                                                                                                            | `routes/auth.ts`                           |
| `HLCC_TRUST_PROXY` is a hop count (0-3), not "trust everything", so `X-Forwarded-For` cannot be used to evade the login limit; limiter memory is bounded                                                                                                           | `app.ts`, `security/rateLimit.ts`          |

| Event streams handle slow clients (no unbounded buffering), end cleanly at shutdown and when a session expires, and always release their slot                                                                                                                      | `routes/api.ts`                            |
| Both images: pinned base digest, no install scripts, non-root, read-only root, capabilities dropped, memory and process limits, bounded logs, authenticated proxy healthcheck                                                                                      | `deploy/Dockerfile`, `deploy/compose.yaml` |

Known residual risks: the proxy's socket mount is writable (safety is its minimality, isolation, authentication and filtering); a compromised proxy could read container names, states and health but not environments, commands or logs; the API-to-proxy link is plain HTTP, authenticated by a shared credential, on a network with no outside route (a process that can read the API's secret file or memory could use it, which is why the proxy is read-only and filtered); the credential is a single shared secret, not per-request signing.

## Not implemented yet

- Environment secret storage and encryption (Phase 7): design requires a key outside the repository and database, masked values, no secrets in audit records.
- Audit coverage for reads and alert delivery (Phase 4).
- Per-request signing or mutual TLS between the API and the proxy (a shared bearer credential is used instead).
- Retention for the audit table (it is append-only by design and grows slowly).
- Response schema validation in the browser (responses are typed, built by the API, and not re-validated client-side).
- Persistent or distributed rate limiting (in memory, single instance).
- Password change and multi-user roles (single admin only).
- Cloudflare Access in front of the hostname. Treat it as an extra layer, not a replacement for the app login.

## Operating guidance

- Bind to loopback (`HLCC_HOST=127.0.0.1`) and publish only via an approved tunnel or Tailscale.
- Set `HLCC_COOKIE_SECURE=true` and `HLCC_TRUST_PROXY=true` behind HTTPS proxies, and list the public origin in `HLCC_ALLOWED_ORIGINS`.
- Never mount the Docker socket into this container. When Docker access is needed, use a separate restricted helper.
- The existing server has world-readable secret files (`shared.secrets`, some `.env`); this project does not read them. Fix their permissions separately.

## Threat notes

Logs, container output and repository text are untrusted data and are never executed or followed. A compromised browser session can only call the same allowlisted, read-mostly endpoints; there is no path from the API to command execution in this release.
